# 共享的客户端连接手册

这份文档讲的是**面板上的一条共享，怎么从别的机器连上去**，以及连不上时先看哪里。

它不解释面板怎么实现，只回答四个问题：

1. 面板上那几个状态各是什么意思，哪一个才代表“现在能连”？
2. Windows / macOS / Linux 分别怎么连？
3. 连上了却写不进去，是谁拦的？
4. 密码到底经过哪些地方，哪些地方绝对不该出现它？

适用范围：P08 起创建的所有共享（协议 `smb`，服务端是本机 Samba）。

---

## 1. 先看状态：三个布尔不是一件事

一条共享上有三个独立的状态。它们经常不一致，而不一致恰恰是有信息量的部分。

| 状态 | 它回答什么 | 为假时人该做什么 |
|---|---|---|
| **配置哈希**（`config_hash`） | 渲染出来的是哪一版定义 | 为空说明这份定义还没被渲染过：点一次“应用” |
| **目录与 ACL**（`directory_prepared`） | 目录建好了、POSIX ACL 按定义设过并核验过 | 去查目录权限：客户端能连上但读写会失败 |
| **配置已写入**（`config_applied`） | 这一段已经写进 Samba 配置并被重载 | 点“应用”或“重新应用” |

再加两个只在特定时刻出现的标签：

- **卷此刻没挂**：这条共享绑定的卷不在挂载状态（`unmounted`、`missing`），标签旁边挂着
  卷的观测值。渲染层**不会**为没挂载的卷写共享段（写出来只会是“一个空文件夹”，比没有更误导）。
- **卷状态读不出来**：卷那边报的是 `unknown` / `error` / `mismatch`——盘可能好好挂着，只是
  面板没读到。这种同样不写配置段，但**别当成盘坏了**：先去卷那一页看挂载与设备身份。
  卷的状态是**卷那一侧的事实**，页面按 `volume_id` 从卷列表取；连卷列表都没取到时，页面
  干脆不显示那一行观测值——不把“不知道”画成“没挂”，否则你会去查一块没坏的盘。
- **运行时已撤销**（`runtime_revoked`）：卷在运行中掉过线，面板把它的段撤掉了。块里带
  撤销时间、当时的卷状态与人读的理由。**卷挂回来它也不会自己恢复**——写配置是要人点头的
  动作。看到这一块，点“重新应用”。

“谁正连着”那一块也要连着看 `service`：`smbd` 没在跑时连接列表同样是空的，而那个空
和“此刻没人用”长得一模一样。

## 2. 谁能连：账号名单与来源网段

两个条件**同时**成立才能连上：

1. **账号在这条共享的名单里**，并且密码是面板设的那个。
   账号在 Samba 的 passdb 里存在但不在名单里，一样被拒——这是“有密码也连不上”的最常见
   原因。名单为空在 Samba 里会退化成 guest 访问，面板因此直接拒绝应用（`SHARE_NO_USERS`）。
2. **来源地址在 `allowed_cidrs` 里**（留空表示不限制来源）。

有一条反直觉的事实必须记住：**Samba 对环回地址（127.0.0.1）永远放行**，`hosts allow`
管不住本机。所以“限定了网段”不等于“只有那个网段能动它”——本机上任何能跑 `smbclient`
的进程都能试。这条在页面里会以 `SHARE_HOSTS_ALLOW_LOOPBACK` 提醒。

权限上限由两处决定，取更严的那个：

- 共享上的**只读**开关（打开时任何账号都是 `r-x`）；
- 每个账号各自的访问级别（只读 / 读写）。

把共享设成只读、再给账号“读写”，结果是只读。这是刻意的：共享级的只读是最后一道闸。

## 3. 客户端怎么连

页面里每条共享都有「客户端怎么连」，给的地址取自**你此刻打开面板用的那个地址**。
如果客户端在别的机器上，把地址里的主机名换成服务器的内网地址（面板不猜自己有多少个
对外地址，它只有网卡计数器）。

### 3.1 Windows 资源管理器

地址栏粘贴：

```
\\服务器地址\共享名
```

回车，提示凭据时填共享账号与密码。要看住凭据不要被记住，用 `net use` 显式控制：

```cmd
net use Z: \\服务器地址\共享名 /user:共享账号 *
net use Z: /delete
```

`*` 让 `net use` 提示输密码，而不是把它写进命令历史（写进命令行的密码会留在
命令历史和进程列表里）。

### 3.2 macOS Finder

Finder →「前往」→「连接服务器…」（⌘K），粘贴：

```
smb://服务器地址/共享名
```

选「注册用户」，填共享账号与密码。命令行等价物是：

```sh
open 'smb://服务器地址/共享名'
```

### 3.3 Linux：挂载（mount.cifs）

这是页面给的那一段，逐条照做。**密码只经标准输入进文件，不进任何进程的 argv**：

```sh
sudo install -d -m 0700 /root/.smb
sudo sh -c 'umask 077; cat > /root/.smb/共享名.cred' <<'CRED'
username=共享账号
password=密码
CRED
sudo chmod 0600 /root/.smb/共享名.cred
sudo install -d -m 0755 /mnt/共享名
sudo mount -t cifs //服务器地址/共享名 /mnt/共享名 \
  -o credentials=/root/.smb/共享名.cred,vers=3.0,uid=$(id -u),gid=$(id -g)
mount | grep 共享名
sudo umount /mnt/共享名
```

四条不能省的细节：

1. **目录先收口**（`0700`）。`umask 077` 只保护 here-doc 建出来的那个文件，不保护目录里
   之后多出来的东西。
2. **写完显式 `chmod 0600`**：here-doc 的权限取决于当时 shell 的 `umask`，显式设一次才
   与“只有 root 能读”这句话对上。
3. **不要写成 `sh -c 'printf "password=…" > …'`**。那种写法密码没挂在 `mount` 的 argv 上，
   却挂在 `sh` 自己的 argv 上，`/proc/<pid>/cmdline` 同机可读——等于没藏。
4. **不要用 `-o password=…`**：同上，而且它会同时出现在 shell 历史与
   `/proc/<pid>/cmdline` 里。

`uid=` / `gid=` 决定挂载点上文件的属主。不带它们，文件属于 root，普通用户只能读。

### 3.4 Linux：不挂载（smbclient）

```sh
smbclient //服务器地址/共享名 -U 共享账号 -m SMB3
```

回车后输密码。`-U` 只给账号名，密码走交互，不进 argv。要从脚本里用，就用凭据文件
（`-A`，权限同样 0600）：

```sh
smbclient //服务器地址/共享名 -A /root/.smb/共享名.cred -m SMB3 -c 'ls'
```

`-m SMB3` 是方言的下限，不是上限：Samba 4 会协商到 `SMB3_11`。留着它是为了在老系统上
不至于掉回 SMB1。

## 4. 连不上：按这个顺序查

在**客户端**上按顺序走，每一步都能独立得出一个结论：

1. **端口通不通**：`nc -z 服务器地址 445`。不通就先看防火墙与 `smbd` 有没有在跑
   （面板上的 `service` 字段；或服务器上 `systemctl status smbd`）。
2. **共享在不在**：服务器上 `smbclient -L //127.0.0.1 -U 共享账号`。列表里没有这条名字，
   说明配置里根本没有它——回面板看「配置已写入」。
3. **身份对不对**：`NT_STATUS_LOGON_FAILURE` 是账号或密码错（**不是**权限问题）；
   `NT_STATUS_ACCESS_DENIED` 是认证过了但不许进这条共享（名单里没有这个账号，或来源网段被拒）。
4. **能进但写不了**：先看共享的只读开关，再看这个账号的访问级别，最后看目录的 POSIX ACL
   （服务器上 `getfacl /srv/upanel/volumes/<卷>/<相对路径>`）。

常见的三个 `NT_STATUS_*` 与它们的含义：

| 错误 | 含义 | 先看哪里 |
|---|---|---|
| `NT_STATUS_LOGON_FAILURE` | 账号或密码不对 | 面板上这个账号的 `has_password`；密码是不是刚改过 |
| `NT_STATUS_ACCESS_DENIED` | 认证过了但这条共享不许进 | 共享的账号名单、`allowed_cidrs` |
| `NT_STATUS_BAD_NETWORK_NAME` | 这条共享不存在（或已停用/已删除） | 面板上的状态、`smbclient -L` 的列表 |

## 5. 密码经过哪些地方

一条共享密码从人手里到 Samba 的 passdb，路径是固定的：

```
人 → 面板输入框 → POST /api/v1/secrets（明文，一次）→ secret_ref
   → share.account.apply（参数里只有 secret_ref）→ smbpasswd -s（明文从标准输入）
```

**不该出现明文的地方**（验收时逐条扫过，命中数必须为 0）：

- 代理日志、Web 日志；
- 代理数据库、面板数据库（含 `-wal` / `-shm`）；
- 任何进程的 `/proc/<pid>/cmdline` 与 `/proc/<pid>/environ`；
- `/proc/mounts`（`mount.cifs` 会把 `credentials=` 剥掉，只看得到 `//主机/共享名`）；
- 任何占位符为“密码”的命令行文本。

**应该出现明文的地方**只有两处：人自己的输入框（取到 `secret_ref` 后立刻清空），
以及 `smbpasswd` 那一次标准输入。

**该有密码的地方**只有一处：`/root/.smb/<名>.cred`（`0600`，目录 `0700`）。它属于
客户端那台机器，不属于服务器；服务器上没有任何文件存这个密码的明文副本，
Samba 侧存的是 NTLM 哈希（`pdbedit -L -v` 能看到 `Password last set`，看不到密码本身）。

## 6. 面板没做的事

- **不装包**：本机缺 `samba` / `cifs-utils` 时面板只报告不可用，不执行 `apt install`
  （PLAN.md 第 10 节）。
- **不改 `hosts deny`**，也不碰 `/etc/samba/smb.conf` 里 `[global]` 以外的任何段；
  唯一的改动是在 `smb.conf` 末尾追加一行 include，指向 `/etc/samba/upanel.d/`。
- **不管客户端**：客户端那台机器上的凭据文件、挂载点、防火墙都不归面板管。
- **不做 SMB1**：方言下限 SMB2/SMB3。老到只支持 SMB1 的设备连不上是预期行为。
