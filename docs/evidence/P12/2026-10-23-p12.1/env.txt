P12.1 验收环境（2026-10-24）
============================

证据类型：**Linux VM integration——两台真实 Ubuntu（22.04.5 / 24.04.5）、真的 sshd、
真的 OpenSSH 主机密钥、真的 restic、真的 SFTP 与本地文件系统** + 宿主 `scripts/check.sh`。
没有浏览器证据：本阶段没有 Web 侧备份页面（`/api/v1/backup/*` 与 UI 是 P12.2—P12.5），
验收全程直接以 `upanel-web` 的身份通过 unix socket 调代理的 `/internal/v1/*`。

验收条件（STAGES §14「P12.1：restic 本地/SFTP 仓库、秘密引用、SFTP 主机密钥验证、
仓库初始化和容量检测」；BACKUP-01「备份后恢复、错误密码、网络断开 → 校验一致，失败不假
成功」与 §14 正文「错误密码/主机密钥拒绝；存储满/网络断开标失败且保留原数据」）。
其中"备份后恢复"要到 P12.2/P12.3 才有对象可验，"存储满"与"中途断网"同理——都写进
result.md 的 NOT RUN，不冒充通过。

两台都是专用虚机（`H:\Code\vms` 之外不入库），宿主物理磁盘没有透传；验收只碰虚机自己
的数据盘与 `/var/tmp`。VM-A 用多线程 TCG（能吃满两核），VM-B 只能单线程 TCG——**这个
速度差不是小事**：同一段只读查询在 VM-B 上要 30 秒上下，在 VM-A 上几秒钟，P12.1 的
"缺陷 C"就是被这份慢照出来的。两台各自独立跑完整一轮（不并发，见下方环境事故 ②）。

为什么另起一个 `p12sftp` 账号
----------------------------
SFTP 目标**不能**用 `upanel-web`：它的登录 shell 是 `/usr/sbin/nologin`、home 是
`/var/lib/upanel`，sshd 执行 `subsystem sftp` 用的是登录 shell，nologin 会让会话直接退出；
而且面板的 Web 身份本来就不该能登进来（这一条本身也是权限边界的一部分）。真实部署里
这个角色是**备份服务器上的那个账号**，所以验收里用一个专用账号 `p12sftp` 更像真实形态。

restic 的两个版本都覆盖到了
---------------------------
22.04 自带 0.12.1、24.04 自带 0.16.4，中间隔了 4 个大版本。产品用的是
`-o sftp.command=<我们自己的 ssh 调用>` + `restic cat config` 读回仓库 id，这两件事在两个
版本上都成立（两台的 §7 全绿、独立 `restic cat config` 与代理读回的 id 逐字节相同）。
脚本把两个版本的原文记进 `payloads/{2204,2404}/restic-versions.txt`，但**不**把"两个版本
行为一致"当验收点——它只证明这两台机器上的这两条路径成立。

环境事故（不是产品缺陷，但必须记）
----------------------------------
① **加速后端**：这台宿主的 WHPX 对 24.04 不稳定，客户机内核会随机
`Attempted to kill init! exitcode=0x0000008b`（一天十几次）。改用 TCG 又踩到
`IO-APIC + timer doesn't work!`——多线程 TCG 起不来，`-smp 1` 与 `-cpu max` 都不管用。
最终 **`-accel tcg,thread=single` 能稳定跑完整轮验收**，代价是每条命令慢一个量级
（P12.1 的时序缺陷正是被这份慢暴露出来的，见 result.md 的"缺陷 C"）。三条失败尝试的
串口原文与决策记在 `docs/TEST_ENVIRONMENT.md` §8.9。
② **跑验收时宿主不许并发**：两台虚机不同时跑验收，宿主也不并发跑 `go test`、不并发
ssh 探测。违反过一次（两台同时跑），结果是一台在 CPU 争抢下握手超时——那一轮的
结论不能当证据，同时也暴露了 result.md 里"缺陷 B"那条产品脆弱点。
