## 单元枚举（验收脚本第 4 节用它做对照）

```
$ systemctl list-unit-files --type=service --no-legend --no-pager | wc -l
251
$ ... | awk '$2=="alias"' | wc -l
20
$ ... | awk '{print $1}' | grep -c '@\.service$'
26
$ systemctl list-units --type=service --all --no-legend --no-pager | wc -l
182
```

接口返回 **239** 个服务单元。它既不是 `list-unit-files` 的行数（251，含 20 个别名），
也不是 `list-units --all` 的 182：前者里的模板名（26 个，其中 `autovt@.service` 同时是别名）
按契约不出现，`list-units` 里还有一批 `not-found` 的单元要补进来。
验收脚本不假设任何一条推导，直接拿“两个枚举的并集 − 模板 − 别名”和接口逐项比对（第 4 节）。

## 这台机器上的关键事实

| 项 | 值 |
|---|---|
| 保护名单命中 | 86 个（`systemd-*` 整体计入核心组件，见 CONTRACTS §10.1） |
| `not-found` 单元 | 21 个（`auditd.service`、`sshd.service`、`NetworkManager.service` …） |
| 别名样本 | `dbus-org.freedesktop.ModemManager1.service` → 规范名 `ModemManager.service` |
| 模板样本 | `apport-coredump-hook@.service` |
| 验收用单元 | `upanel-accept.service`（正常）、`upanel-accept-fail.service`（`ExecStart` 不存在） |
| Web 监听 | `127.0.0.1:19449`（`PORT` 可改），进程身份 `upanel-web`（uid 999） |
| 代理 | root，socket `root:upanel-web`，非 0666 |
