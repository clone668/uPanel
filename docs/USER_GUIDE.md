# 用户手册（uPanel 1.0）

这份手册讲**装上之后怎么用**。装之前的事看 [INSTALL.md](INSTALL.md)，怎么把浏览器连上看
[ACCESS.md](ACCESS.md)，坏了怎么救看 [RECOVERY.md](RECOVERY.md)，哪些事这一版做不到看
[KNOWN_LIMITATIONS.md](KNOWN_LIMITATIONS.md)。

一句话定位：uPanel 是**一台** Ubuntu 服务器的管理面板。它替你做那些"必须 root 才做得成"的事，
但每一件都先给你看要改成什么样、改完由它自己核对结果，并且全程留下记录。

---

## 1. 第一次登录

安装脚本第 12 步会要你设一个管理员密码（至少 12 个字符，输入不回显）。装完之后：

1. 浏览器打开面板地址（默认只监听回环 `127.0.0.1:9443`，怎么从自己的电脑访问见 ACCESS.md）；
2. 用安装时给的用户名（默认 `admin`）和你设的密码登录；
3. 装完建议做两件事：**开二次验证**（设置 → 二次验证，同一页还能打印一次性恢复码），
   以及**换掉安装时那个口令**。注意 1.0 **没有"改密码"的界面**——换口令只有两条路：
   本机 root 跑 `upanelctl reset-password --config /etc/upanel/upanel.json`，
   或者管理员调 `POST /api/v1/users/:id/password`（见第 3 节）。

登录失败有速率限制：同一账号 15 分钟内错 5 次、同一来源 IP 错 20 次就会被暂时挡住，
到时间自动恢复，**不会永久锁死**。忘了密码看 RECOVERY.md 第 1 节（`upanelctl reset-password`）。

> 模拟器/极慢的机器上登录可能要好几秒（Argon2id 的代价）。这不是卡死了。

## 2. 界面长什么样

左侧导航固定 16 项，只显示**已经实现**的模块：

| 导航 | 页面 | 一句话 |
|---|---|---|
| 概览 | `/` | 主机、CPU、内存、负载、网络与磁盘概要 |
| 应用 | `/apps` | 应用卡片、启停、分组与搜索；本机候选确认成应用 |
| ↳ 部署 | `/apps/deployments` | 受管 Compose 部署的现场、更新与回切 |
| 存储 | `/storage` | 磁盘、分区、文件系统、拓扑、健康与容量；写操作自 1.0 起开放 |
| ↳ 设备详情 | `/storage/devices/<dev>` | 单块盘的现场：分区表、SMART、依赖 |
| 共享 | `/shares` | SMB / NFS 共享定义与客户端连接说明 |
| ↳ 账号 | `/accounts` | 受管 Linux 账号、SSH 公钥、受限 sudo 模板 |
| 服务与进程 | `/services`、`/processes` | systemd 单元与进程；启停/信号经预检与任务 |
| 文件 | `/files` | 受管理文件根内的浏览、预览、下载与写入 |
| 终端 | `/terminal` | 受限 Web 终端（降权、无 sudo、一次一许可） |
| 日志 | `/logs` | journald 查询与实时流 |
| 备份 | `/backup` | restic 仓库、策略、快照、备份/恢复/验证/清理 |
| 计划任务 | `/schedules` | systemd timer 与受管理脚本 |
| 网络 | `/network` | 网卡、路由、监听端口、防火墙 |
| 更新 | `/updates` | 软件包事实、可升级、安全更新、重启标志 |
| 监控告警 | `/alerts` | 历史曲线、告警规则、事件确认、通知投递账 |
| 任务中心 | `/jobs` | 所有任务的列表、状态机、事件流与日志 |
| 设置 | `/settings` | 本机账号安全（TOTP 与恢复码）；`/settings/host` 能力探测 |

导航里那一项 **"容器"仍然是空的**：容器与镜像没有独立页面，容器的查看与启停走"应用"页
（逐条列在应用卡片下面）。这是有意留的——用别的页面去占那一格就是超承诺。

## 3. 两种角色

| 角色 | 能做什么 |
|---|---|
| **admin** | 全部已实现的管理操作 |
| **viewer** | 只能看**标注了 V 的只读接口**，服务端返回脱敏数据；不能做任何写操作、看不到原始日志 |

没列出来的权限默认拒绝。角色可以由管理员调整，**但不能自我提权**，也不能删除最后一个可用管理员。

**注意：1.0 的面板上没有"用户管理"页面。** 面板自己的账号（admin / viewer）只能通过 HTTP API 管理：
`POST /api/v1/users` 建号、`PATCH /api/v1/users/:id` 改角色或停用、`POST /api/v1/users/:id/password` 改密码、
`DELETE /api/v1/users/:id` 删号（均需管理员 + 再认证，字段见 CONTRACTS.md 第 2 节）。
界面上只有"本机账号安全"（TOTP）那一页。"共享 → 账号"页管的是**被管理的 Linux 账号**，
不是面板登录账号——两者是不同的东西，别混。

第一个管理员由安装脚本创建（`upanelctl init-admin`），密码忘了用 `upanelctl reset-password`。

## 4. 每个写操作都有四个阶段

这是理解整个面板的钥匙。你点一个"执行"，背后永远是这四步：

```
预检（preflight）→ 提交任务（job）→ 代理执行 → 结果核对 + 审计
```

1. **预检**：面板把参数规范化后交给代理，代理**只看不动**，回答三件事——能不能做、要不要再认证、
   要输入什么确认短语。预检有有效期，过期或用同一份预检换了参数，提交会被拒。
2. **提交任务**：拿到预检返回的票据再提交。这一步起，操作变成一条**任务**，有状态机
   （排队 → 执行中 → 成功/失败/取消）、有资源锁、有幂等键——同一份预检提交两次不会执行两次。
3. **执行**：代理用自己的身份去做，全程不接受 shell 字符串，只接受"程序 + 参数数组"。
4. **核对与审计**：执行完代理会**读回真实状态**（不是只看退出码），对不上就报失败并回滚（能回滚的）；
   成功与失败都写审计，秘密字段落库前脱敏。

所以：**不要**在"任务中心"里看不到这条任务的时候以为它没发生。所有写操作都在那里。

### 需要"再认证"和"短语"的动作

再认证 = 重新输一次你的密码（+ TOTP）。短语 = 一个必须手抄的动作词，防止手滑。

| 动作 | 再认证 | 短语 |
|---|---|---|
| 改 IPv4 / 改防火墙规则 | ✅ | `RECONFIGURE` |
| 初始化分区表 / 删分区 | ✅ | `INIT` / `DELETE` |
| 建分区 | ✅ | —（要预检与再认证，但不动已有数据） |
| 格式化 | ✅ | `FORMAT` |
| 挂载/卸载卷、改 fstab | 卸载与配置要 | — |
| 删文件（目录递归） | ✅ | `DELETE` |
| 覆盖已存在的文件（上传） | — | `OVERWRITE` |
| 删软件包 | ✅ | `REMOVE` |
| KILL 进程 | ✅ | `KILL` |
| 从备份恢复 | ✅ | 覆盖已有数据时是 `OVERWRITE`（不覆盖就不给短语） |
| 清理旧快照 | ✅ | `DELETE` |
| 电源（重启/关机） | ✅ | — |
| 建受管账号 / 改 sudo 模板 | ✅ | — |
| 部署更新、删除部署 | ✅ | — |
| 测试类动作（验收用） | — | `PROBE` |

规律：**不可逆的、会把机器改到连不上自己的、会覆盖已有数据的**，都要再认证 + 短语。

## 5. 各模块怎么用

### 5.1 概览

主机名、系统版本、CPU、内存、负载、网络与磁盘概要。数字全部来自代理的实时采集，页面**不做乐观更新**
——刚做完一个操作，概览可能还显示上一轮的事实（代理 5 秒采一次、前端按自己的节奏取），这是如实呈现，不是不生效。

### 5.2 存储

- **看**：磁盘、分区、文件系统、挂载点、SMART 健康、容量、依赖链（谁挂在哪、谁是谁的分区）。
- **写**（全部要预检 + 任务）：初始化 GPT 分区表、建/删分区、格式化（ext4/XFS）、导入卷、
  挂载/卸载、改 fstab 托管项、忘记卷。
- **保护**：系统盘（以及它上面挂着的 LVM/RAID/swap）**从结构上**无法被格式化或删分区——不是靠你再确认一次。
- **注意**：磁盘被格式化**没有**自动恢复路径。面板拦得住"误操作",拦不住"你要的数据本来就不在备份里"。

### 5.3 共享与账号

- **共享**：建 SMB 或 NFS 定义 → 绑定一个受管理卷 → 面板生成配置、`testparm`/`exportfs` 校验、
  写入并 reload。客户端怎么连见 [SHARES_CLIENT.md](SHARES_CLIENT.md)。
- **账号**：面板只管理**它自己创建的**账号；已有系统账号一律只读。可以改显示名、加 SSH 公钥、
  套用**固定模板**的 sudo 规则（不接受手写 sudoers）。
- **依赖检查**：账号还在被共享或文件引用时删不掉，面板会点名是谁在用它。

### 5.4 应用与部署

- **应用页**：本机发现的容器与单元按"运行状态"和"入口状态"分开显示；把本机已有的东西"确认成应用"
  才会被面板管理；一键启停走预检与任务。依赖卷缺失时**不会**被启动。
- **部署页**：只认**受约束的部署定义**（镜像、端口、卷、健康检查），不接受原始 Compose YAML、
  `privileged`、`docker.sock`、危险宿主挂载。更新会记录镜像 digest、按需备份、起完做健康探测，
  失败可以回切到上一版——**回切不回切数据**。

### 5.5 服务与进程

- 单元：启动/停止/重启/开机自启，受保护名单内的单元（面板自己、sshd、dbus 等）动不了。
- 进程：按 PID + 启动时刻定位（防止 PID 复用打错人），TERM 可以直接发，KILL 要再认证 + 短语。

### 5.6 文件

- 只能操作**受管理文件根**：安装脚本默认登记一个根 `srv` → `/srv/upanel`（可写）。根是配置文件里的
  白名单（`agent.files.roots`），不是"默认整个文件系统"——留空等于**没有**文件管理。路径逐段检查，
  符号链接不跟随，`..` 出不去。
- 浏览、预览文本、受控下载；写入 ≤ 1 MiB，先备份再替换；上传走暂存，完成后才落到目标位置。
- `chmod`/`chown` 只允许普通权限位与**受管理**账号/组，禁止 setuid/setgid 与任意 UID。

### 5.7 终端

受限终端：以 `upanel-shell` **降权**运行（非 root、无 sudo），创建要再认证，连接用**一次性许可**，
数量与时长都有上限，会话关闭即失效。它是"给一个人临时敲几条命令"的工具，不是后门。

### 5.8 日志

按数据源、单元、级别与时间窗口查 journald，可以实时订阅。单页 ≤ 1000 行 / 1 MiB，窗口 ≤ 24 小时；
**原始日志只有管理员能看**，viewer 看不到。

### 5.9 备份

- 先建**仓库**（`local` 目录或 `sftp`），密码只走 `RESTIC_PASSWORD`，私钥只放 tmpfs，
  指纹必须你确认过。
- 再建**策略**（收哪些路径、保留多少个、什么时候跑）。
- 然后才是 `backup.run`；快照可以浏览、可以**抽样验证**、可以按保留策略清理、可以恢复。
- 恢复要选目标根目录 + 相对路径，默认不覆盖，覆盖要显式勾。恢复完成后依然要做业务验证——
  **"备份成功"和"恢复后能用"是两件事**。

### 5.10 计划任务

用 systemd timer 表达"什么时候跑什么"。页面把四件事分开显示：定义是什么、单元装上了没、
enable 了没、timer 在不在跑。可以跑的动作限定在登记过的列表里，脚本只写在固定目录、归属 `upanel-shell`。
内置的定时身份（备份、证书续期）审计里会写明"是定时器干的"，和人工操作分开。

### 5.11 网络

- **看**：网卡与地址、路由与默认网关、监听端口与占用进程、防火墙规则。
- **改**：单块物理网卡的 IPv4（DHCP 或静态 + 网关 + DNS），只对 systemd-networkd 管理的网卡开放；
  其它情况页面会给出"为什么不能改"。
- **安全网**：改之前先挂一个独立回滚 timer（跑的是代理自己的二进制，面板挂了也照退）。你改完之后
  要在**新地址**上重新连上并确认；超时、关浏览器、面板崩，都会退回去。
- **防火墙**：只动带面板标记的 UFW 规则；混用 nftables/iptables 时整体只读。

### 5.12 更新

已装软件包、候选版本、可升级项、安全更新、是否需要重启。安装/升级/删除都要预检，删除另要短语 `REMOVE`；
**禁止隐式 dist-upgrade**——升哪些包必须由你点。

### 5.13 监控告警

- 历史曲线按粒度保留；**数据缺失画成断开，不画成 0**。
- 告警规则（指标 + 阈值 + 持续多久）、事件、确认；静默窗口。
- **通知投递账**：哪一次告警到底发没发出去、失败原因是什么——这条比"告警响了"更重要。

### 5.14 任务中心

所有写操作的唯一入口记录。可以看状态、看事件流、看脱敏日志；能取消的才给取消按钮。

### 5.15 设置

本机账号安全：开启 TOTP（扫码 → 确认 → 展示**一次性恢复码**，抄下来）、关闭 TOTP。
这一页**只有二次验证**，没有改密码——口令只能走 `upanelctl reset-password` 或那条管理 API。
`/settings/host` 是能力探测：这台机器上缺哪个外部程序、版本多少——它只说真读到的事，读不到就写"读不到"。

## 6. 常见任务配方

**加一个只能看的同事（1.0 只能走 API）**
`POST /api/v1/users`（管理员 + 再认证）建号并给角色 `viewer` → 把初始密码线下交给对方。
**对方自己改不了密码**（1.0 没有这个界面，也没有给 viewer 的自助接口）：要换口令得管理员再调一次
`POST /api/v1/users/:id/password`，或本机 root 跑 `upanelctl reset-password`。
viewer 看不到原始日志，也只拿脱敏字段。界面上暂无用户管理页，见第 3 节的说明。

**加一块新数据盘**
存储 → 选中空盘 → 初始化 GPT → 建分区 → 格式化 ext4/XFS → 导入卷 → 挂载 → 在共享/应用里用它。
每一步都是一条任务，出问题去任务中心看那一条的日志。

**给一个目录开通 SMB**
共享 → 新建共享 → 选卷与路径 → 建共享账号并设口令（口令只进密文库）→ 保存时面板会跑 `testparm` →
把 SHARES_CLIENT.md 里对应系统的连接方法发给对方。

**把面板搬到新地址**
网络 → 选网卡 → 写新地址 → 保存后会挂回滚 timer → 在新地址上重新打开面板并确认 →
确认之后回滚自动取消。**不要**只在旧地址上点"看起来还行"。

**备份一次，再验证一次**
备份 → 建仓库（第一次要初始化）→ 建策略 → 运行一次 → 看到快照后跑一次抽样验证。
只有抽样验证过，你才知道密码、私钥、仓库路径都对。

## 7. 出问题先看哪里

| 现象 | 先看 |
|---|---|
| 点了按钮没反应 / 说不清成功没有 | **任务中心**：那条任务的状态与日志 |
| 某个页面说"依赖未安装" | 设置 → 能力探测（`host-caps`），它会说缺哪个程序、装它要什么命令 |
| 某个功能只读、给了一段原因 | 看那段原因：多半是"这台机器上不是 networkd/UFW/ext4"这类边界 |
| 谁在什么时候改了什么 | 审计（管理员可见，含被拒绝的高风险操作） |
| 登录不上、证书报错、代理连不上、库坏了 | [RECOVERY.md](RECOVERY.md) |
| 磁盘/fstab 出事 | [STORAGE_RECOVERY.md](STORAGE_RECOVERY.md) |

面板不替你做的事，写在 [KNOWN_LIMITATIONS.md](KNOWN_LIMITATIONS.md) 里，故障现场值得先翻一遍。
