# 完整证据索引（uPanel 1.0）

这份索引是**地图**，不是结论本身。每一行指向一个目录，结论以目录内的 `result.md` 与原始输出为准。
按约定，证据类型必须标明——**宿主上的单测通过不等于 Ubuntu 上能用**。

| 记号 | 含义 |
|---|---|
| VM | Ubuntu 虚拟机上的真机验收（Linux VM integration） |
| 宿主 | 开发宿主上的检查（build / vet / go test / 前端 / smoke），**不证明 Linux 行为** |
| 浏览器 | 真浏览器打真面板（Playwright + 真机） |
| 文档 | 只有阅读与人工核对，没有自动断言 |

目录约定：`docs/evidence/<阶段>/<日期>[-<子任务>]/`。

## 怎么用这份索引

1. **想知道某功能验过没有**：先看 `SUPPORT_MATRIX.md`，再看这张表对应的行，最后打开那个目录的 `result.md`。
2. **想复现**：每个 P16 目录都有驱动脚本或探针脚本；更早的目录里是当时用的脚本副本与 `run.log`。
3. **想确认"这一版能承诺什么"**：`KNOWN_LIMITATIONS.md` 的 A 节（未验证）比任何"已通过"列表都重要——
   它列的是**没有读数**的地方。

## 证据规则（摘自 `docs/evidence/README.md`）

1. 证据必须来自实际执行。未执行的写 `NOT RUN` 并说明补做方式，不写"理论上通过"。
2. 区分证据类型（宿主单测 / mock 集成 / Linux VM / 浏览器 / 人工观察），在 `result.md` 顶部标明。
3. 不提交磁盘镜像、内存转储、私钥、密码、代理密钥、真实用户数据、journal 全量导出。
4. 需要脱敏时保留结构、替换敏感值，并在文件头注明"已脱敏"。
